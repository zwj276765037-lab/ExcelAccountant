# ExcelAccountant 本地凑数工具设计规格

日期：2026-09-02

状态：已由用户批准，等待书面规格复核

目标仓库：`https://github.com/zwj276765037-lab/ExcelAccountant`

## 1. 产品目标

ExcelAccountant 是一个完全本地运行的 Windows 桌面软件。用户选择一个 `.xlsx` 工作簿、一个单列金额范围和一个或多个目标金额，软件从该列中寻找互不重复的源单元格组合，使每个组合分别精确等于对应目标金额。

每个输出文件代表一套完整分配方案。在同一个输出文件中，每个源单元格最多使用一次，不同目标用不同颜色高亮。不同输出文件是相互独立的备选方案，因此允许复用同一批原始单元格。

金额计算必须使用工作簿中实际保存的完整十进制值，不得截断、四舍五入或主动统一小数位。精确和近似方案都只能在用户手动勾选后输出；近似输出必须显著标记实际合计与差额，并要求人工复核。

## 2. 明确范围

### 2.1 第一版支持

- Windows 10/11 桌面环境。
- 普通 `.xlsx` 工作簿。
- 单个工作表中的一个金额列或一个单列范围。
- 一次输入一个或多个目标金额。
- 数百个候选金额的常见会计匹配场景。
- 正数、负数和不同小数位的金额。
- 多套精确完整方案，一套方案一个输出文件。
- 无精确完整方案时，在界面显示最多 5 套整体互斥的近似方案，允许经风险确认后输出。
- 完全离线运行，不上传文件，不收集遥测。
- 输出文件可使用 WPS 或 Microsoft Excel 打开。

### 2.2 第一版不支持

- `.xls`、`.xlsm`、加密或需要密码的工作簿。
- 跨多个工作表或多个金额列共同搜索。
- 公式单元格作为候选金额。
- 自动重新计算工作簿公式。
- 含宏、复杂绘图、形状、外部对象或其他无法保证安全往返保存的工作簿输出。
- 云端协作、用户账户、网络服务或 WPS 插件。

检测到不支持的输入或工作簿结构时，软件必须停止相关操作并给出明确原因，不得降级精度或冒险生成可能损坏的文件。

## 3. 核心业务规则

### 3.1 源金额身份

每个候选金额以源单元格地址作为唯一身份，内部记录至少包含：

- 工作表名称；
- A1 单元格地址；
- 原始存储文本；
- 精确十进制值；
- 整数化后的求解值；
- 行号、列号；
- 源数据类型；
- 是否隐藏；
- 是否为公式。

金额相同但地址不同的单元格是不同项目。任何算法排序、去重或缩放都不得丢失地址映射。

### 3.2 单元格使用约束

- 在一套完整方案中，一个源单元格只能分配给一个目标，或者不使用。
- 同一源单元格不得同时出现在两个目标组合中。
- 每个目标必须由至少一个源单元格组成；空集合不是合法组合。
- 不同输出文件之间允许复用源单元格，因为每个文件代表一套独立备选方案。
- 对相同金额的重复目标，目标仍是独立业务项；但仅交换两个相同目标标签、而源组合集合不变的结果不重复输出。

### 3.3 精确金额规则

- 直接读取 `.xlsx` 内保存的原始数值文本，不以二进制浮点数作为求和真值。
- 目标金额保留用户输入的完整十进制字符串。
- 以所有候选金额和目标金额的最大小数位建立公共十进制尺度，只在右侧补零后转为整数。
- 转换不得删除有效小数、截断或进位。
- 数值相等按数学金额判断，因此 `1.2`、`1.20` 和 `1.200` 相等。
- 整数化后可先除以所有非零候选值及目标值的最大公约数，减少求解系数，但必须保留可逆映射。
- 在进入 OR-Tools 前检查所有系数、可能的总和及目标是否处于安全整数范围。超过求解器安全范围时报告错误，不得自动降低精度。
- Excel/WPS 在写入工作簿前已经丢失的精度无法恢复；软件保证不在文件现有精度之上制造新的舍入。

### 3.4 候选数据识别

- 数值单元格：使用工作簿中实际保存的数值文本。
- 严格数值文本：允许可选正负号、规范千位分隔符和十进制小数；去除千位分隔符后按十进制解析。
- 币种符号、混合文字、日期、布尔值、错误值和无法严格解析的文本：不参与搜索，并列入异常数据清单。
- 公式单元格：第一版不参与搜索，并列出地址及原因。
- 零值单元格：默认不参与搜索，因为不会改变目标合计却会制造大量等价组合；界面显示被排除数量。
- 负数：作为有效金额参与搜索。
- 隐藏行：属于用户指定列的全部数据，默认参与搜索；预览区显示隐藏行数量。
- 第一行若不能严格解析为金额，则视为表头并跳过；其他无法解析的行全部列入预览和异常清单。

搜索前必须显示候选数量、异常数量、公式数量、零值数量、隐藏行数量和完整数值预览。用户确认后才能开始搜索。

## 4. 用户界面与操作流程

### 4.1 主界面输入

1. 选择或拖入 `.xlsx` 文件。
2. 工作簿只有一个工作表时自动选择；存在多个工作表时必须从下拉框选择。
3. 金额范围支持以下三种输入：
   - Excel 列字母，例如 `E`；
   - 从 1 开始的列序号，例如 `5`；
   - 单列 A1 范围，例如 `E2:E500`。
   - 只输入整列时，实际扫描范围截止到该列最后一个非空单元格，不遍历工作表的全部最大行数。
4. 界面显示列字母、列序号和检测到的表头，例如“E 列 / 第 5 列 / 交易金额”。
5. 目标金额采用可增删的表格输入，每行包含目标编号和完整金额字符串。
6. 允许相同目标金额重复出现，它们仍作为独立业务项处理。
7. 精确方案数量默认 20，允许设置为 1 至 100。
8. 单次搜索时限默认 60 秒，允许继续搜索或设置更长时限。
9. 提供“开始搜索”“取消搜索”“继续搜索”和“打开输出目录”按钮。

### 4.2 搜索前确认

搜索前展示：

- 工作簿名和工作表名；
- 选定列或范围；
- 候选金额及地址预览；
- 目标金额列表；
- 有效、异常、公式、零值、隐藏行计数；
- 将使用的公共小数尺度；
- 方案数量上限和搜索时限。

存在异常数据时必须由用户明确确认继续，不能静默忽略。

### 4.3 精确结果

- 找到的每套方案显示目标、组成金额、地址、精确合计和颜色。
- 每套方案生成一个独立文件，命名为 `原文件名_方案001.xlsx`、`原文件名_方案002.xlsx` 等。
- 默认最多生成 20 个文件，用户可设置 1 至 100。
- 找到上限时停止并标注“结果已截断，可能还有其他方案”。
- 搜索超时时，已找到并验证通过的精确完整方案仍可输出，同时标注“搜索未完成，可能还有其他方案”。
- 如果超时时尚未找到精确方案，不生成文件，状态必须是“在当前时限内未找到”，不能声称“已证明无解”。

### 4.4 近似结果

当求解阶段没有找到任何精确完整方案时，程序可计算并显示最多 5 套整体互斥的近似方案：

1. 仍满足一个源单元格最多分配给一个目标。
2. 第一优化目标是最大化精确命中的目标数量。
3. 第二优化目标是最小化所有目标绝对差额之和。
4. 第三优化目标是最小化任一目标的最大绝对差额。
5. 第四排序键是使用源单元格总数，优先较少项目以便人工复核。
6. 每个目标显示目标金额、近似金额、有符号差额、绝对差额、组成地址和组成金额。
7. 允许某个目标在近似方案中未分配任何单元格，但必须醒目标注“未分配”。
8. 近似结果可勾选输出；输出前必须风险确认，文件名、结果表和复核状态必须标明“近似”，并记录实际合计、有符号差额和绝对差额。

若精确求解器已证明不可满足，状态显示“已证明不存在精确完整方案”；若精确搜索超时，状态显示“精确搜索未完成，以下仅为参考近似方案”。

如果已经找到精确完整方案，但工作簿因安全预检失败而禁止输出，则界面只展示该精确方案和禁止输出原因，不启动近似求解，也不把“文件未生成”误报为“没有精确方案”。

## 5. 输出工作簿设计

### 5.1 原文件保护

- 原始工作簿永不覆盖。
- 搜索开始前记录原文件哈希。
- 输出先写入目标目录下的临时文件，验证通过后再原子重命名为最终文件。
- 任何写入或验证失败时删除临时文件。
- 完成后再次核对原文件哈希，确保原文件未变化。

### 5.2 高亮与结果表

- 仅改变选定金额单元格的填充色，不修改整行，避免破坏其他列格式。
- 同一个目标在一个文件中使用同一种颜色，不同目标使用不同颜色。
- 颜色按目标顺序确定，保证同一批方案文件中的颜色含义一致。
- 新增“凑数结果”工作表，记录：方案编号、目标编号、目标金额、颜色、组成金额、组成地址、精确合计和复核状态。
- 结果表顶部明确说明“同一文件中每个源单元格最多使用一次”。
- 若目标数量较多导致颜色相近，结果表仍以目标编号和地址作为审计真值，颜色只作为视觉辅助。

### 5.3 工作簿安全预检

第一版只对安全预检通过的普通 `.xlsx` 输出文件。预检至少检测：

- 宏或 VBA 部件；
- 图表、绘图、形状、嵌入对象；
- 外部链接或外部数据连接；
- 加密、密码或无法解析的 OOXML 部件；
- 受保护且禁止写入的目标工作表；
- 其他已知无法安全往返保存的结构。

预检失败时可以继续在界面显示求解结果，但不得生成工作簿，并必须说明具体不支持项。

## 6. 系统架构

推荐技术路线为 Python 桌面程序：

- PySide6：桌面界面、表格预览、拖放、进度和后台任务。
- 原始 OOXML 读取器：从工作表 XML 获取精确数值文本，并通过工作簿关系映射工作表。
- openpyxl 元数据适配器：获取工作表、单元格类型、样式和安全检查辅助信息；不得把浮点读取结果作为金额真值。
- OR-Tools CP-SAT：多目标、互斥分配、精确可行性、近似优化和备选方案枚举。
- openpyxl 安全输出器：只在预检通过的普通 `.xlsx` 副本中设置填充色和结果表。
- PyInstaller：先生成 one-folder 测试包，验证通过后生成 Windows one-file 发行包。

模块边界：

1. `ui`：只负责交互和展示，不包含金额计算。
2. `xlsx_reader`：返回带地址的原始候选记录和工作簿能力报告。
3. `decimal_codec`：严格解析十进制并生成可逆整数尺度。
4. `solver_exact`：寻找并枚举精确完整方案。
5. `solver_approximate`：在无精确方案时生成可人工复核的近似方案。
6. `xlsx_writer`：复制、着色、生成结果表并写入临时文件。
7. `output_verifier`：独立重读并验证输出。
8. `worker`：后台执行、进度、取消和超时传播。

模块之间只传递结构化领域对象，不共享可变工作簿或界面状态。

## 7. 求解模型

对每个候选单元格 `i` 和目标 `j` 建立二元变量 `x[i,j]`：

- `x[i,j] = 1` 表示候选单元格 `i` 分配给目标 `j`。
- 对每个候选单元格：`sum_j x[i,j] <= 1`。
- 对每个目标：`sum_i amount[i] * x[i,j] = target[j]`。
- 对每个目标：`sum_i x[i,j] >= 1`，禁止空组合。

每发现一套完整分配，加入排除该完整分配的 no-good 约束，再继续搜索下一套。方案唯一性按“目标到源地址集合的映射”判断；相同目标间仅标签互换的等价结果经过规范化后去重。

近似模型引入每个目标的正负偏差变量，并按第 4.4 节的优先级分阶段优化。所有系数均为无损整数化后的金额。

## 8. 状态与错误处理

程序必须使用以下明确状态：

- `EXACT_COMPLETE`：已完成搜索并找到精确方案。
- `EXACT_TRUNCATED`：已达到方案数量上限，可能还有方案。
- `EXACT_TIMEOUT_WITH_RESULTS`：搜索超时，但已有可验证的精确方案。
- `NO_EXACT_PROVED`：求解器已证明不存在精确完整方案。
- `EXACT_NOT_FOUND_TIMEOUT`：搜索超时且未找到精确方案，不能推断无解。
- `APPROXIMATE_READY`：近似方案已就绪，可经风险确认后勾选输出。
- `INVALID_INPUT`：文件、范围、目标或金额格式无效。
- `UNSAFE_WORKBOOK`：工作簿求解可进行，但禁止生成文件。
- `OUTPUT_VERIFICATION_FAILED`：输出验证失败，临时文件已删除。
- `CANCELLED`：用户取消，停止后续求解和写入。

用户界面不得把“超时”“取消”“输入无效”显示为“无解”。

## 9. 输出独立验证

每个临时输出文件必须重新打开并独立验证：

1. 每个目标的组成金额逐位精确等于目标金额。
2. 每个目标至少包含一个源单元格。
3. 同一源地址在整个方案中只出现一次。
4. 结果表记录的地址、金额、目标和颜色与高亮单元格一致。
5. 方案编号、目标数量和颜色映射一致。
6. 输出工作簿结构完整且可以重新加载。
7. 原文件哈希保持不变。

只有全部验证通过，临时文件才能转为正式输出文件。

## 10. 测试策略

### 10.1 单元测试

- 完整小数、尾随零、极大小数位和负数解析。
- 不同小数位无损整数化、最大公约数缩减和安全范围检查。
- 严格文本金额、千位分隔符和非法混合文本。
- 零值、日期、布尔值、错误值和公式排除。
- 颜色与目标编号的稳定映射。

### 10.2 求解器正确性

- 小规模随机数据使用暴力枚举作为真值，对照精确求解器。
- 单目标、多目标、重复目标、负目标和目标为零。
- 重复金额但不同地址。
- 精确方案、无解、多个方案和等价方案去重。
- 任一源单元格跨目标重复使用必须被拒绝。
- 近似方案的精确目标数量、总绝对差额和最大差额排序。
- 超时与取消状态不得误报为无解。

### 10.3 Excel 集成测试

- 单表、多表、列字母、列序号和单列范围。
- 表头、空白、文本金额、隐藏行、日期和公式。
- 安全普通 `.xlsx` 的复制、高亮、结果表和重读验证。
- 含图表、形状、宏、外部链接或保护的工作簿必须触发安全拒绝。
- 文件被占用、输出目录不可写和磁盘错误。
- 当前示例工作簿的端到端测试，但示例金融文件不得提交到公开仓库。

### 10.4 打包验收

- Windows 10 和 Windows 11。
- 未安装 Python 的干净环境。
- WPS Office 和 Microsoft Excel 分别打开输出文件。
- one-folder 与 one-file 包均运行正确。
- 大几百条候选金额、多目标和默认 60 秒时限的性能基准。

## 11. 验收标准

第一版完成必须同时满足：

1. 能选择普通 `.xlsx`、工作表和单列金额范围。
2. 能输入多个完整十进制目标金额。
3. 计算过程中不发生任何金额舍入。
4. 同一输出方案中不存在重复使用源单元格。
5. 精确方案和近似方案都只能经用户手动勾选后生成文件；近似文件必须显著标注差额和风险。
6. 每套完整方案独立输出，默认 20 套、最多 100 套。
7. 不同目标颜色不同，并包含可审计的“凑数结果”工作表。
8. 没有精确输出时显示最多 5 套近似方案，用户可在风险确认后勾选输出。
9. 超时、无解、取消和输入错误状态严格区分。
10. 原文件不被修改，输出必须经过独立重读验证。
11. 不支持或不安全的工作簿不得冒险输出。
12. 软件可在未安装 Python 的 Windows 环境离线运行。
13. 自动化测试和示例端到端测试全部通过。

## 12. 仓库与数据安全

- 公开仓库只提交源码、文档、测试代码、生成式测试数据和构建配置。
- `source/`、`output/` 以及所有真实 Excel 文件默认由 `.gitignore` 排除。
- 不提交真实流水、账号、单位名称、目标金额或其他财务数据。
- 测试工作簿必须由测试代码生成，或使用完全虚构的数据。

## 13. 后续实施顺序

本设计经书面复核后，另行编写详细实施计划。实施计划应按以下风险顺序推进：

3. 近似优化与状态语义；
4. Excel 安全预检、输出和独立验证；
5. PySide6 界面与后台任务；
6. 打包、端到端测试与发布文档。
